Diagnosis: LIVE vs STABLE counter contract

The previous report (8/32 pass) characterised the dominant failure as post-run TOTAL_HITS=0 while per-channel hist_bin shows real hits. The root cause is the histogram counter contract documented verbatim in histogram_statistics_v2_hw.tcl:

TOTAL_HITS and DROPPED_HITS are LIVE CURRENT-INTERVAL counters.
LAST_INTERVAL_TOTAL_HITS and LAST_INTERVAL_DROPPED_HITS latch the
completed interval just before the live counters reset, allowing
stable one-second rate polling.

CSR 13 (TOTAL_HITS) maps to the VHDL signal csr_total_hits, a live accumulator that is cleared at every interval_pulse -- one pulse per INTERVAL_CFG clock cycles. On this build histogram_statistics_0.interval_reset is wired only to the generic POR reset bridge, so the periodic timer is the sole source of pulses.

The previous sweep configured INTERVAL_CFG = 4 s · 125 MHz = 500M cycles, which fires four interval pulses inside a 4 s run window. The post-end-run read of CSR 13 therefore returned the partial t=3..4 s bucket (often zero), and the bank-swapped hist_bin reflected one second of activity rather than the full run.

Fix. scripts/cotest/phase4_5_sweep.py now programs INTERVAL_CFG = INTERVAL_CFG_NEVER_FIRE = 0xFFFFFFFF (34.36 s @ 125 MHz, longer than any row in the matrix). No interval pulse fires during the run window; CSR 13 accumulates the full run total; the ping-pong bank does not swap, so hist_bin[0..255] reads the same accumulator. The snapshot now captures all three counters and reports a hist_bin_sum_matches_csr13 cross-validation flag.

Run Window Normalization

Sim and board run the same emulator configuration but with very different RUN windows: sim defaults to 10 ms (1,250,000 cycles at 125 MHz) while board defaults to 4000 ms (4 s). Absolute hit counts therefore diverge by approximately 400x even when the per-channel rate is identical.

The Δ% rate column normalizes to hits per millisecond:

sim_hits_per_ms   = sim_total_hits / sim_run_ms
board_hits_per_ms = board_total_hits / board_run_ms
delta_pct_rate    = (board_rate - sim_rate) / sim_rate * 100

A Δ% rate near zero means sim and board agree on the per-channel hit rate. Large Δ% values indicate real behavioral divergence (FIFO saturation, CSR-write race, lane-admit failure, etc.) and are the only actionable comparison across mismatched run windows.

A new sim convention (RUNNING stage = 1 ms sharp) is being adopted to make direct comparisons even cleaner; once new sim evidence at 1 ms RUNNING lands, this report will refresh automatically. Long-soak runs (10 s+) are flagged explicitly in their row notes.

Saturation Analysis

The Phase 4.5 sweep now uses the OPQ bottleneck as the primary denominator. BASIC rows request less than 125 Mhit/s aggregate, which is 50% of the 250 Mhit/s OPQ operational ceiling. PERF rows request at least that boundary and include explicit saturation probes above the ceiling.

active_channels = popcount(channel_mask) * popcount(lane_mask)
per_active_channel_hps = rate_88fp * (125e6 / 65536)
requested_hps = per_active_channel_hps * active_channels
theoretical_hits = min(requested_hps, 250e6) * run_ms / 1000
sim_delta_pct = (sim_total - theoretical_sim_hits) / theoretical_sim_hits * 100
board_delta_pct = (board_total - theoretical_board_hits) / theoretical_board_hits * 100

The two theory deltas are independent. They do not use the other side as the reference. The normalized sim-vs-board Δ% rate remains in the table only as a third comparison.

Findings & Interpretation

The live-vs-stable contract is now stable

Across all 32 rows, hist_bin_sum_matches_csr13 is true. The histogram_statistics_v2 live counter (CSR 13) and the dual-bank SRAM accumulator agree on every row. With INTERVAL_CFG_NEVER_FIRE, the LIVE counter is no longer subject to a t=last_pulse..end_run partial-window race against the post-end-run sc_tool read.

Histogram ingress receives no hits in this run

Every row reports PORT_STATUS = 0x000000FF (per-port hit_fifo empty bits all set, fifo_level_max = 0) and UNDERFLOW = OVERFLOW = DROPPED_HITS = 0. The arb_hit_type0_supercore shows lane ingress_emu_hits growing across rows, so the emulator and arb stages are functional. The path from arb egress to histogram ingress is delivering nothing on this build, across all 32 rows. The previous run's 8 PASS rows are not reproducible in this session.

Sanity-negative rows still PASS

Rows p45_025 and p45_031 (lane_mask=0x00) PASS by expectation: every counter is zero, which is the correct outcome when arb blocks every lane. These rows are now the only two PASSes, but their pass remains a true positive.

Next-step hypotheses (handed off)

  • The ingress mux selector (HIST_INGRESS_BASE_WORD = 0x0AB00) acknowledges the post-rbCAM selection (status & 0x7 == 0x3) but no traffic reaches the histogram's per-port hit_fifos. STP coverage of the histogram asi_data* ports would localise the gap.
  • The histogram's CONTROL.apply appears to settle (bit 0 self-clears, CONTROL = 0x100), but BANK_STATUS = 0 across every row of this run -- compared with the prior run where PASSed rows had BANK_STATUS = 1. Worth checking whether the first interval_pulse (in the legacy 4 s INTERVAL_CFG) was acting as a side-effectful 'arm' that the never-fire value no longer provides.

Methodology

The single-integrated sweep runner is scripts/cotest/phase4_5_sweep.py. Each row of the 32-row inline plan programs the arb_hit_type0_supercore lane mask, the emulator_mutrig channel mask, hit rate, and hit mode, and the histogram_statistics_v2 LEFT/RIGHT/BIN_WIDTH/KEY_LOC CSRs. The histogram INTERVAL_CFG is now hard-set to INTERVAL_CFG_NEVER_FIRE = 0xFFFFFFFF so the LIVE current-interval counters (csr_total_hits, CSR 13; csr_dropped_hits, CSR 14) accumulate the full run without being reset by an interval_pulse. The runner then drives the runctl_mgmt_host_0 LOCAL_CMD opcode sequence 0x10 → 0x11 → 0x12 → (wait 4.0 s) → 0x13. The driver polls CSR_STATUS until host_state=IDLE (2 s timeout, wall-clock fallback). After the run the 256 histogram bins are read one word at a time per the single-word readout requirement (Round 3 a710b11a finding).

Verdict computation now captures three independent hit counters and a tolerance-based cross-validation flag: total_hits_csr13 from the LIVE accumulator, last_interval_total_hits_csr17 from the STABLE post-interval-pulse latch (should be 0 or stale under INTERVAL_CFG_NEVER_FIRE), and hist_bin_sum from the 256-bin readout. The PASS predicate uses total_hits_csr13 as the authoritative full-run total. A hist_bin_sum_matches_csr13 mismatch is logged as a warning, not a fail.

Every sc_tool call is serialised through swb_ring_lock. The forbidden opcodes 0x30 / 0x31 are explicitly blocked in the runner. After the on-board portion of the sweep completes the bench ticket is released back to the queue.
