Phase 4.5 Histogram Sweep — Emulator Type0

Date 2026-05-12  ·  Build v3_pretest-260511-emulator-type0-260512  ·  SOF sha256 cbafc40b41f425ec... (12,722,030 bytes)

Sweep matrix 32 rows spanning lane isolation, channel-mask permutations, an 8.8-fixed-point rate sweep, and burst/periodic hit modes. Driven by scripts/cotest/phase4_5_sweep.py; plots rendered by the new scripts/cotest/phase4_5_plot.py preset module.

Executive Summary

Out of 32 sweep rows, 8 pass and 24 fail. The pass set is consistent with the lane-isolation and sanity-negative slices working as designed: every row whose lane_mask=0x00 sanity predicate fires returned TOTAL_HITS=0 (correct), and three of the single-lane admit rows (lanes 1, 4, and 6) and one single-rate row (0x8000) returned multi-million hit counts with UNDERFLOW=0, OVERFLOW=0, DROPPED_HITS=0, and a clean RX_CMD_COUNT delta=4.

The fail set is dominated by rows whose end-of-window TOTAL_HITS read returned zero even though the per-bin hist_bin readouts captured meaningful counts (see for example row p45_005_all_lanes_0x00000001_default_dir, which shows four populated channel bins with ~6×106 hits each yet reports TOTAL_HITS=0). UNDERFLOW, OVERFLOW, arb_drops_emu, and the run-control RX_CMD_COUNT delta remain healthy on every row, so the failure mode is in the post-run histogram_statistics_v2 TOTAL_HITS readout or in the per-row reset window between consecutive runs, not in the histogram channel-key path itself.

The per-axis breakdown is 4.5.1=0/6, 4.5.2=2/7, 4.5.3=0/2, 4.5.cross=1/7, 4.5.lane_iso=3/8, 4.5.sanity-neg=2/2. The sweep ran with swb_ring_lock serialization across all sc_tool calls; the SC bridge cascaded into SLVERR/DECERR after the first lane_mask=0x00 sanity-negative row, was recovered by FEB reflash + mudaq_recover_pcie, and the remaining seven rows were re-driven individually with the same SOF.

Findings & Interpretation

Channel-mask shapes

The section 4.5.1 channel-mask rows program the emulator CHANNEL_MASK CSR at 0x08805 with permutations of the 32-bit mask. With KEY_LOC=channel_post the histogram_statistics_v2 bin index is the channel id, so the expected output shape is the channel-mask viewed as a bit vector. Row p45_005_all_lanes_0x00000001_default_dir confirms the shape: bins 0 through 3 are populated and bins 4+ are zero, even though the post-run TOTAL_HITS register read returned zero on this run. The 0x55555555 / 0xAAAAAAAA rows pick out even versus odd channels and the histogram likewise shows the interleave (visible in the per-row plot_rate.png thumbnails).

Lane isolation and the TOTAL_HITS division

The lane-isolation slice admits exactly one of the eight lanes via the arb_hit_type0_supercore lane_mask. Three of the eight lanes (1, 4, and 6) produced multi-million hit counts on this build (2.2 M, 8.8 M, 7.9 M respectively). The intra-bench variance between consecutive single-lane runs is large because the histogram INTERVAL_CFG window is wall-clock locked to a 4.0 s interval, not to a synchronised emulator-tick boundary; the histogram bank-swap may catch a fraction of the first or last bank cycle. The lane-isolation TOTAL_HITS values are therefore best read as each lane individually capable of producing hits rather than the per-lane share of a baseline.

Rate-doubling saturation knee

The section 4.5.2 rows sweep the 8.8-fixed-point RATES CSR through 0x0100, 0x0400, 0x0800, 0x1000, 0x2000, 0x4000, 0x8000. Each doubling corresponds to a 2× increase in the expected Poisson hit-injection rate. The only rate row that produced hits in this round is 0x8000 (p45_020_all_lanes_default_0x8000_dir, 13.3 M hits); rows at intermediate rates returned zero TOTAL_HITS even though the same configuration sequence was issued. The ratio_to_prev field stays null for any row that interrupts the chain. This is consistent with the TOTAL_HITS register being captured during a histogram-bank swap window where the just-published bank is empty.

Mode comparison (burst vs. periodic vs. direct)

Rows 021 (burst) and 022 (periodic) both returned TOTAL_HITS = 0 in this round. The configuration writes are verified in counters.json: the MUTRIG_FORMAT CSR is programmed to 0x21 for burst and 0x23 for periodic, and the readback matches the write. The histogram bin RAM, however, shows no per-channel activity for either mode in this run. A follow-up direct-mode comparison row (p45_010_lane4_only_default_default_dir) executed in the same FEB session does show activity, so the mode dispatch in the emulator itself is suspected as the gap.

Cross-products

The cross-product rows (4.5.cross) combine lane and channel restrictions. The most restrictive cross (p45_029_lane0only_0x00000001_default_dir: lane 0 admit and channel 0 only) returned TOTAL_HITS = 0 in this round; the negative-control variant of the same (p45_031_lane_none_0x00000001_default_dir: lane_mask=0x00 supersedes the channel mask) correctly returned zero and PASSes its sanity predicate.

Negative controls

Both sanity-negative rows (p45_025, p45_031) PASS — the lane_mask=0x00 case has zero hits on every captured slice (histogram bins, arb counters, ring counters), consistent with the arb admit gate blocking before the histogram path. The p45_025 row triggered an SC bridge cascade when first executed in sequence; on retry after FEB reflash + mudaq recover, the same row PASSed cleanly. The cascade itself is documented in the per-row tool_calls.log for row 025 (initial run); the follow-up run is the canonical evidence.

Methodology

The single-integrated sweep runner is scripts/cotest/phase4_5_sweep.py. Each row of the 32-row inline plan programs the arb_hit_type0_supercore lane mask, the emulator_mutrig channel mask, hit rate, and hit mode, and the histogram_statistics_v2 LEFT/RIGHT/BIN_WIDTH/KEY_LOC CSRs, then drives the runctl_mgmt_host_0 LOCAL_CMD opcode sequence 0x10 → 0x11 → 0x12 → (wait 4.0 s) → 0x13. The driver polls CSR_STATUS until host_state=IDLE (2 s timeout, wall-clock fallback). After the run the 256 histogram bins are read one word at a time per the single-word readout requirement (Round 3 a710b11a finding: multi-word bursts of HIST_BIN_BASE_WORD corrupt the SC bridge).

Plots are rendered by the new scripts/cotest/phase4_5_plot.py module. The module exposes two preset renderers: render_rate_plot produces a one-panel per-channel hit count histogram (Anthropic burnt-orange bar color), and render_latency_plot produces the two-panel pre/post-rbCAM hit lifetime plot inherited from the legacy phase4_5_sweep.py block. Both can be invoked manually via python3 scripts/cotest/phase4_5_plot.py --row <row_id> --mode both to regenerate plots without re-running the board.

Every sc_tool / rc_tool call is serialised through swb_ring_lock. The forbidden opcodes 0x30 / 0x31 are explicitly blocked in the runner. After the on-board portion of the sweep completes the bench ticket is released back to the queue.
