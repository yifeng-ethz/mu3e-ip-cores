Executive Summary

Out of 32 Phase 4.5 sweep rows, the directed source-RTL sim passes 32/32 and the dualport on-board build passes 25/32 (7 FAIL). The on-board pass rate climbed from 2/32 on the prior pre-dualport emulator-type0 build to 25/32 on this build — the histogram counter contract is no longer the dominant failure. The 32-row sim baseline provides the reference truth against which every on-board counter is now compared in the table below.

Of the 7 board FAILs, three (p45_017, p45_019, p45_030) are HIST_DROPPED_HITS_NONZERO at the highest rate-knob settings, two (p45_018, p45_020) are isolated TOTAL_HITS_ZERO rate-knob rows, and two (p45_025, p45_031) are sanity-negative rows where the on-board lane_mask=0x00 path is leaking traffic that the sim correctly predicts to be zero.

Run Window Normalization

Sim and board run the same emulator configuration but with very different RUN windows: sim defaults to 10 ms (1,250,000 cycles at 125 MHz) while board defaults to 4000 ms (4 s). Absolute hit counts therefore diverge by approximately 400x even when the per-channel rate is identical.

The Δ% rate column normalizes to hits per millisecond:

sim_hits_per_ms   = sim_total_hits / sim_run_ms
board_hits_per_ms = board_total_hits / board_run_ms
delta_pct_rate    = (board_rate - sim_rate) / sim_rate * 100

A Δ% rate near zero means sim and board agree on the per-channel hit rate. Large Δ% values indicate real behavioral divergence (FIFO saturation, CSR-write race, lane-admit failure, etc.) and are the only actionable comparison across mismatched run windows.

A new sim convention (RUNNING stage = 1 ms sharp) is being adopted to make direct comparisons even cleaner; once new sim evidence at 1 ms RUNNING lands, this report will refresh automatically. Long-soak runs (10 s+) are flagged explicitly in their row notes.

Findings & Interpretation

Sim closure: 32/32 PASS

The compact feb_swb_corun directed sim covers all 32 sweep rows with the run-control opcode sequence 0x10 → 0x11 → 0x12 → 0x13, the emulator + arb + histogram chain wired identically to the on-board datapath, and the same INTERVAL_CFG=0xFFFFFFFF never-fire contract. Every row reports sim_total_hits == hist_bin_sum within 0 hits and the per-lane arb selected_count matches sim_total_hits within at most 128 cycles of plant settle.

Board closure: 25/32 PASS on the dualport build (up from 2/32 pre-dualport)

The dualport build v3_pretest-260511-emutype0-dualport-260512 raises histogram-counter closure from the prior 2/32 emulator-type0 build to 25/32. The legacy 4 s INTERVAL_CFG live-vs-stable race is no longer the dominant failure: every PASSed board row reports csr13_TOTAL_HITS in the ~14M..~270M range against a sim baseline of ~0.16M..~1.65M, and the sanity-positive predicate (total_hits_gt_0) is satisfied.

Remaining 7 board FAILs (handed off)

  • p45_017_all_lanes_default_0x1000_dir — HIST_DROPPED_HITS_NONZERO
  • p45_018_all_lanes_default_0x2000_dir — TOTAL_HITS_ZERO
  • p45_019_all_lanes_default_0x4000_dir — HIST_DROPPED_HITS_NONZERO
  • p45_020_all_lanes_default_0x8000_dir — TOTAL_HITS_ZERO
  • p45_025_lane_none_default_default_dir — TOTAL_HITS_NOT_EXPECTED_FOR_SANITY_NEG
  • p45_030_lane_evens_default_0x2000_dir — HIST_DROPPED_HITS_NONZERO
  • p45_031_lane_none_0x00000001_default_dir — TOTAL_HITS_NOT_EXPECTED_FOR_SANITY_NEG

The cluster of HIST_DROPPED_HITS_NONZERO rows are the high-rate channel-mask sweeps where the emulator rate overruns the histogram ingress; on sim those same rows pass because the compact harness runs a shorter window and the dropped-hits predicate is not exercised. The TOTAL_HITS_ZERO rows p45_018 and p45_020 are isolated rate-knob failures inside the otherwise-passing 0x0100..0x8000 sweep, suggesting a non-monotonic CSR behaviour that the sim-side total_hits_gt_0 predicate did not catch. The two TOTAL_HITS_NOT_EXPECTED_FOR_SANITY_NEG rows are the negative controls (lane_mask=0x00) - they PASSed on the prior build but now report csr13>0 on dualport; the sim correctly predicts 0, so the board side is leaking traffic through arb despite the per-lane disable. This is the only true sim-vs-board functional inversion in the matrix.

Sim and board agreement summary

25/32 rows agree (sim PASS & board PASS). 0/32 rows agree negatively (sim FAIL & board FAIL). 7/32 rows split (sim PASS & board FAIL). 0/32 rows are reverse-split (sim FAIL & board PASS).

Methodology

The 32-row sweep plan is the single source of truth in scripts/cotest/phase4_5_sweep.py. The plan was exported to /tmp/p45_plan.json with --export-plan; no local edits to that script.

Sim side. Each row compiles a per-row testbench phase4_5_sim_row_<row_id>_tb under firmware_builds/systems/system_20260504_emulator_type0/tb_int/feb_swb_corun/uvm/sequences/. The compact harness instantiates emulator_mutrig + arb_hit_type0_supercore + histogram_statistics_v2 wired with the same emulator CSR, arb lane-mask, and histogram LEFT/RIGHT/BIN_WIDTH/KEY_LOC values used on board. Histogram INTERVAL_CFG=0xFFFFFFFF never-fire so CSR 13 (LIVE) accumulates the full run. Make targets: comp_phase45_sim_rows, run_PHASE4_5_SIM_ROW row_id=<rid>, run_PHASE4_5_SIM_ALL. Sim run_cycles default to 500,000,000 at 125 MHz (the on-board 4 s window); the captured evidence here was produced with run_cycles=1,250,000 for fast turnaround.

Board side. Same plan driven by scripts/cotest/phase4_5_sweep.py, every sc_tool call serialised through swb_ring_lock. The runner programs arb lane mask, emulator channel mask + rate + mode + cluster, histogram LEFT/RIGHT/BIN_WIDTH/KEY_LOC/INTERVAL_CFG_NEVER_FIRE, then drives 0x10 → 0x11 → 0x12 → (wait 4.0 s) → 0x13 and reads CSR 13, CSR 17, and the 256-bin histogram.

Plots. Both sim and board sides render through scripts/cotest/phase4_5_plot.py's render_rate_plot + render_latency_plot. The sim latency plot is a placeholder — the compact harness has no rbCAM timestamp split, so only the rate axis carries real comparison data.

Board evidence: v3_pretest-260511-emutype0-dualport-260512/sweep_evidence/<row_id>/. Plot script: scripts/cotest/phase4_5_plot.py.
