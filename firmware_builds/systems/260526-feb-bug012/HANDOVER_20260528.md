### `cfg_in_port` (histogram_statistics_v2 CSR bug)

CONTROL bits [3:2] = `csr_in_port`. Default = `IN_PORT_FILL_CONST` (0b00). For Type1 delay-mode, **MUST set CONTROL[3:2]=01 (IN_PORT_EXT0_CONST)** so `port_ts(0)` reads `asi_hit_type1_extended_0_data[86:39]` (the 48-bit true ts driven from `mts_processor.hit_out_debug_timestamp`). Without this, hit_ts defaults to `asi_type1_up_ts` (zero in many configurations) and the histogram is meaningless.

Correct CONTROL value for delay-mode TYPE1_UP + EXT0:
```
ctrl = (1<<16) | (1<<12) | (1<<8) | (1<<4) | (1<<2) | 1
     = source_sel=TYPE1_UP | reset_baseline | apply | mode=delay(1) | in_port=EXT0 | start
```

## Histogram delay-mode RTL paths (for slope-=-1 model)

`histogram_statistics_v2.vhd:925-940` (`build_delay_key_from_ts`):
```vhdl
gts_full_v := resize(gts_value, DELAY_TIMESTAMP_WIDTH_CONST);  -- 48-bit
hit_full_v := resize(hit_ts, DELAY_TIMESTAMP_WIDTH_CONST);     -- 48-bit
delay_v    := gts_full_v - hit_full_v;                          -- 48-bit
-- Then truncate to SAR_TICK_WIDTH=21 bits
```

`hit_ts` source for `cfg_in_port=EXT0`:
- `port_ts(0) <= asi_hit_type1_extended_0_data(86 downto 39)` (`histogram_statistics_v2.vhd:1062`)
- That field is set by `mts_processor.vhd:2243`: `extended_data_v(86 downto 39) := hit_out_debug_timestamp`
- `hit_out_debug_timestamp` is `tcc_div_quotient_d` (when `delay_ts_field_use_t = 1`) — i.e. the **MTS divider quotient reconstructing the 8ns timestamp from TCC** (`mts_processor.vhd:2097`)

`gts_8n` (the free-running reference):
- Resets only on `run_state_cmd = SYNC` (level term, NOT pulse), then increments every 8ns
- `histogram_statistics_v2.vhd:1132`: `gts_counter_clear <= i_rst or runctl_reset_hold or bool_to_sl(run_state_cmd = SYNC)`

**The reconstruction failure mode:** `tcc_div_quotient_d` requires the prediv to track the hit arrival pattern. Under headersync injection, hits arrive in irregular bursts (1 fire per 1550c, each burst contains 7 hits at 6c spacing). If the divider's expected_latency CSR (silicon: 2000c) doesn't match the actual MTS pipeline latency for this hit pattern, the reconstructed ts drifts.
